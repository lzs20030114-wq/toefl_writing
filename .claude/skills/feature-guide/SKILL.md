# 功能介绍图：真实页面 → 原位标注 → 3:4 竖图

一套图 = 4–6 张 3:4 竖图，每张讲主流程里的一步。全部由 `scripts/feature-guides/` 的管线生成：
真浏览器打开本地 dev server（就是线上同一套组件）拍电脑版页面，元素坐标从页面里量，标注另叠一层。
现成样板：成图 `docs/feature-guides/vocab/`（单词本 5 张），脚本 `scripts/feature-guides/vocab/`。

## 定稿的规矩（用户 2026-10-05 拍板，直接照做，不必再出样张试错）

这些都是用户否掉过别的做法之后定下的，所以每条都有来由：

1. **截图一律电脑版网页**（1440×900），成图是 **3:4 竖图**（1080×1440）给手机看。
   用户否过「手机页面截图」——网站主要在电脑上用，图要和用户看到的一样。
2. **一页的结构固定**（样张 A）：左上标题（≤9 字）+ 一两句说明；右上整页缩略图，橙框标出下面放大的是哪一块；
   下面是放大的真实截图，橙圈圈住元素、标签贴在旁边用线连上；最多一行脚注。
   `lib/poster.mjs` 已经按这个版式写好，照着用，不要另起版式。
3. **标签贴在元素的真实位置旁边**。不要编号图例、不要另起一栏解释、不要用文字描述位置——
   要讲的东西不在画面上（菜单、弹窗、展开态），就把它点开再拍一张真实画面。
4. **文案是说明，不是口号**：直接说「这是什么、怎么用」。
   - 被否的：小标题「要会写的词 / 记得之后再拼一遍」（标语腔）；
     「不想练拼写的词，在卡片右上角 ⋯ 里关掉『要会写』」（用文字指路）。
   - 认可的：「点一下英文单词」「这个词的几个意思 / 点一个，就按这个意思收藏」；
     「不想练拼写：关掉『要会写』」——线直接连到截图里那个开关上。
5. **只讲主流程，一套 4–6 张**。小结弹窗、结算页、结果核对这类打开就看得懂的页面不单独出图，
   有用的信息并进相邻页的标签或脚注。用户否过 12 张的拆法：「不必拆解得这么细」。
6. 每页 3–6 个标签；标签主句 ≤14 字、副句 ≤20 字；脚注一行（≤38 个汉字）。

## 流程

### 0. 定页面清单

- 先读这个功能的组件，把主流程（入口 → 核心操作 → 结果）和交互摸清：按钮文案、快捷键、Pro 限制、要什么数据。
- 列 4–6 页，每页一行：`标题｜拍哪个画面｜标哪几条`。粒度参照单词本那套：

  | 页 | 拍哪个画面 | 标哪几条 |
  |---|---|---|
  | 查词和收藏 | 解析页点词弹出的词典 | 点词、音标发音、复习方式、点义项=收藏、直接收藏、AI（Pro） |
  | 打开单词本 | 首页左栏入口 + 今日复习卡 | 入口和角标、今日词数、阅读/听力两个开始按钮 |
  | 阅读复习 | 翻面后的复习卡 | 高亮的词、答案、忘了 / 记得 |
  | 拼写 | 拼写卡 + 点开的 ⋯ 菜单 | 填进空里、核对、看答案、关掉「要会写」 |
  | 听力复习 | 翻面后的听力卡 | 播放、翻面才显示、没听懂 / 听懂了 |
- 用户没指定页面时，把清单发一条消息，等一句「可以」再拍（拍错一组很费时间）；
  用户已经给了清单或说「直接出」，就跳过这步。

### 1. 起环境

```bash
npx next dev -p 3100        # 要一直开着：本机另开终端，或用 Bash 工具的 run_in_background 起
                            # 云端沙箱：(setsid nohup npx next dev -p 3100 > dev.log 2>&1 &)
curl -s -o /dev/null -w "%{http_code}" http://localhost:3100/    # 200 才往下走
```

- 浏览器：云端自动用预装的 `/opt/pw-browsers/chromium`；本机（Windows）第一次用先 `npx playwright install chromium`，
  或设 `PW_CHROMIUM=<本机 Chrome 路径>`。
- 发过新公告后，先把 `lib/browser.mjs` 里 `QUIET` 的 `toefl-announcement-dismissed` 改成 `data/announcements.json`
  最新的 id，否则每张截图都带公告弹窗。

### 2. 新建一套

```bash
cp -r scripts/feature-guides/_template scripts/feature-guides/<套名>    # 套名用英文短名，如 mistakes
```

模板里的 `capture.mjs` / `build.mjs` 能直接跑（拍首页、出一张示例图），套名取文件夹名，复制后不用改名。

### 3. 演示数据（页面需要数据时）

- 图里的数据要像真用户在用：**用网站自己的代码生成**，内容取自题库真实素材，不手编。
  单词本那套是 `vocab/seed.mjs`：临时探针页 `app/zz-<套名>-seed/page.js` 把 lib 里的函数挂到 window 上跑，
  跑完在 finally 里删掉探针页（CLAUDE.md 的约定），随机数换成固定种子，结果快照提交成 `<套名>/*.json`。
- localStorage 里的数据：`newCtx(browser, { seed: { 键: 值 } })` 首次加载前写入。
- 接口数据：`ctx.onApi` 接管对应 `/api/*`；没接管的一律回 `{ ok: true }`。页面空白或报错时，
  打印 `ctx.apiLog` 看页面调了哪些接口、缺哪个。
- AI 生成的文字（批改、讲解）只能 mock 成示例，并在那一页脚注写明「图中 AI … 是示例」。

### 4. 拍图（`<套名>/capture.mjs`）

- 每组一个 `if (want("组名")) { … }`，每个画面 `wd.saveMeta(await snap(page, wd, "画面名", specs))`：
  存截图 + 要标注的元素框。`specs = { 名字: { text, tag?, exact? } | { aria } }`，按看得见的文字取最小元素。
- 要讲的展开态（⋯ 菜单、弹窗、悬浮层）点开后另拍一张，拼版时用第二块放大图讲它。
- 网站有随机顺序时截图不稳：`ctx.addInitScript(() => { Math.random = () => 0.999999; })`。
- 时钟是装好的假时钟（停在 `NOW`）：界面要等计时/动画就 `page.clock.fastForward(毫秒)`。
- 一律 1440×900。单词本复习页在 769–1280px 宽有已知的布局挤压 bug，别用那个宽度。
- 跑：`node scripts/feature-guides/<套名>/capture.mjs [组…]`（只重拍某几组就带组名）。
- 看：`node scripts/feature-guides/peek.mjs <套名> <画面> [x y w h [倍数]]` 出局部放大图，同时打印元素框。
  定 crop、核坐标都靠它，别对着 4320px 原图猜。

### 5. 拼版（`<套名>/build.mjs`）

开写前先读 `references/poster.md`（拼版接口、版面尺寸、标签摆位的套路、踩过的坑）。要点：

- 每页 `def("NN-标题", (n, total) => { const p = page(K, {…}); …; return p; })`，文件名就是成图名。
- 坐标一律从 meta 取（`K.box` / `K.boxByText`），不要手估；量不准的先 peek。
- 放大区的上下边切在行距、卡片缝里，别切半行字；标签放在截图的空白处或压暗区，连线别横穿文字。

### 6. 出图自查

```bash
node scripts/feature-guides/<套名>/build.mjs && node scripts/feature-guides/render.mjs <套名>
# → .work/<套名>/out/NN-标题.png，另有一张总览 .work/<套名>/sheet.png
node scripts/feature-guides/render.mjs <套名> p3      # 只改了一页就只出那一页
```

用 Read 逐张看成图（不是看 HTML），对照：

- 每个标签指对了元素；标签没盖住它要讲的东西；连线没穿过文字；标签之间不挤不叠。
- 放大区边缘没有被切掉一半的文字行；缩略图上的橙框和放大区对得上。
- 脚注一行没折行；说明 ≤3 行；内容没超出画布底部。
- 看 `sheet.png`：整套风格一致，没有哪一张特别挤或特别空。

### 7. 文案核对

每条说明都对着代码核一遍（grep 组件）：快捷键、数量上限、Pro 限制、按钮实际行为。
例：单词本「再拼一次」写成「只练习、不改结果」，是因为代码里写着「本次仍按首次拼写结果排期」。
图里的具体数字来自演示数据，别把它写成规则。

### 8. 交付

```bash
node scripts/feature-guides/render.mjs <套名> --publish    # 拷进 docs/feature-guides/<套名>/
```

删页、改名之后，先 `git rm` 掉 `docs/feature-guides/<套名>/` 里旧的 png 再 publish（publish 只覆盖、不清理）。

- 把成图发给用户（有 SendUserFile 就用），一句话列出各页标题，注明演示数据、示例文字。
- 提交 `scripts/feature-guides/<套名>/` 和 `docs/feature-guides/<套名>/`（`.work/` 不入库）；
  推送按仓库惯例，用户说「推」走 /ship。
- 拍图途中发现网站 bug：写清复现、根因、修法，等用户拍板再修，不顺手改（CLAUDE.md 的约定）。

## 用户提意见时

- 「太细 / 太多」→ 合并相邻步骤、砍掉自解释的页面，留 4–6 张。
- 「看不懂 / 不知道在哪」→ 补拍真实状态，把标签挪到元素旁边，不要加文字指路。
- 「字太多 / 像广告」→ 标签只留「是什么 + 怎么用」，删形容词。
- 要改的是版式本身（不是某一套）→ 改 `lib/poster.mjs`，再把已有的几套重出一遍，保持全站一致。
