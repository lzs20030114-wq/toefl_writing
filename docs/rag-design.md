# 练习答疑窗口（题内有据问答）设计方案

> 状态：设计稿，未实施（2026-10-12）。本稿只做设计，不改代码、题库与线上配置，也没有调用付费模型。
> 讨论记录：Claude 项目「TreePractice RAG 功能设计方案」。

## 1. 结论与定位

- **第一期做「练习记录答疑窗口」**：挂在逐题回顾里，用户就**这一道题**追问。比如「这句为什么这么说」「长难句怎么拆」「这个词什么意思」「为什么不选 B」。
- **第二期再做「错题本复盘」**：按时间段总结错误趋势与规律，给出建议（见 §10，本期不实施）。
- 用户提出两个入口时，最初的目标是「先从可信材料里找答案、标出处、材料里没有就说不知道」。这条纪律两期都保留。

### 这算不算 RAG

算，但属于轻量版。准确的叫法是**基于当前题的有据生成（grounded generation）**。

- 检索这一步几乎为零：用户打开的是哪道题本来就知道，直接把这道题的「证据包」（§3）整份交给模型。**不需要向量库、文本切块和 embedding。**
- 真正的检索只有两处：
  1. **词典**：问到单词或短语时，先查本地 ECDICT（`public/dict/`，34,778 词条，`lib/dict/lookup.js`），把词条放进证据包。
  2. **方法库**（第二期）：按题型写的定位方法和陷阱类型说明，按题型直接取，同样不需要向量检索。
- 好处：便宜，几乎不多花上下文；准确，证据就是这道题本身；也没有新的基础设施要维护。

| 讲解外观 | `components/shared/AiExplainView.js` | 窗口展开态从这里长出来 |

| 划词词典 | `components/reading/WordLookupLayer.js` + `lib/dict/` + `lib/dict/aiSense.js`（语境义项） | 选中一句或一个词后直接发问，复用这套选区 |

**关键缺口：真题库没有解析。** `data/realBank/reading/ap.json` 435 题、`rdl.json` 309 题，带 `explanation` 的都是 0 题。生成库 `data/reading/bank/ap.json` 的 505 题都带解析，但那是 AI 写的。所以真题只能靠「原文 + 标准答案 + 学生作答」来推理，引用原文是硬要求（§4）。

## 3. 证据包（每道题交给模型的全部材料）

统一结构，按科目填字段：

```
[题型] AP / RDL / CTW / LCR / LC / LA / LAT / BS
[原文] 按句编号：S1 … Sn（阅读用 passage；听力用 transcript / announcement / 对话逐行；
       听力句子与 sentence_timings 同序，引用 S7 时前端可以直接 ▶ 点播那一句）
[题干] [选项 A-D] [标准答案] [学生作答]（未作答也写明）
[参考解析] 只有生成库有，标注「AI 生成库自带，仅供参考」；真题这一栏为空
[词典] 用户问到的词：ECDICT 释义（+ 已有的语境义项缓存）
[本题已有讲解] 第一轮讲解文本（追问时带上，避免前后说法不一致）
```

- 句子编号由前端切分，用的是现有切句逻辑（`lib/reading/passageLayout.js`、`SentenceTranscript`）。AP 选句题已经有 S1..Sn 键（`lib/reading/sentenceSelection.js`），直接沿用。
- 长度：AP 原文最长约 1,900 字符，加上题目和多轮历史远低于 40,000 字的上限。沿用 `MAX_PASSAGE_CHARS = 4000` 兜底，**原文不截断**（截断导致编造的教训见 `useReadingAiExplain.js` 头注）。
- 第一期覆盖：阅读（CTW / RDL / AP）、听力（LCR / LC / LA / LAT）、拼句。写作和口语已有评分报告（`WritingFeedbackPanel`、`useInterviewAiReview`），证据换成「题目 + 作答 + 评分报告 + 评分标准」，放到第一期之后。

## 4. 回答纪律：引用与「不知道」

写进 system prompt，并由前端校验：

1. **先给证据再下结论。** 每个结论后面标出处：`[S3]` 表示原文第 3 句，`[词典:anchor]` 表示词条，`[答案]` 表示标准答案。讲陷阱时用现有陷阱类型的口径：偷换概念、过度推断、范围扩大或缩小、原文未提、张冠李戴等。
2. **标准答案是权威。** 模型不得改判答案。如果它认为答案有问题，只能说「这题答案与原文可能有出入」，并在前端打一个「可能有误」的上报入口，接到现有审核流（`data/realBank/audit-overrides.json` 那一套人工核对），不当场翻案。
3. **超出证据就说不知道。** 问题需要这道题以外的知识时（例如出题人背景、别的题、考试政策），回答「这道题的材料里没有这个信息」，可以给一句通用常识，但必须标「非本题材料」。
4. **纯文本输出**（面板是 pre-wrap 渲染，沿用现有「不要 markdown」规则）。

前端校验（零成本，不调模型）：

- 引用的 `Sx` 必须存在。如果回答里用引号引了原文，引文要能在对应句里找到（忽略大小写与标点）。校验不过的引用降级为灰色「未核实」，不渲染成可点的出处。
- 每条回答在 UI 上把 `[S3]` 渲染成可点的小标：阅读点了高亮原文那句，听力点了播放那句。

## 5. 交互

- **入口**：逐题回顾里每道题现有的「AI 讲解」按钮，点开后就是窗口的第一轮。手机上用 `components/shared/BottomSheet.js`，桌面在题目侧展开，**不悬浮在整页报告上**。这样问题天然绑定了题，不会出现「你问的是哪道」。
- **选区提问**：在原文里选一句或一个词，选区工具条多一个「问这句」按钮，问题里自动带上 `[选中: S5]` 或这个词（同时触发查词典）。
- **预设问题**（chips，点一下即发）：
  - 「为什么不选我选的」（错题默认）／「正确答案的依据在哪」
  - 「拆解这句长难句」（要求先选句）
  - 「这个词在这里什么意思」（要求先选词）
- 自由输入框 + 追问。**每题最多 6 轮**，超过后提示「这题聊得够多了，可以去练错题」。

## 6. 多轮实现（不改 `/api/ai`）

- 每轮 message = 证据包 + 最近几轮问答（超长时从最早的问答开始丢，证据包永不丢）+ 本轮问题。
- 新增一个共享 hook（暂名 `useQuestionQa`），收敛现有 5 个讲解 hook 的骨架：Pro 门、错误映射 `mapAiHelperError`、缓存、计费时机。各科只提供 `buildEvidence(detail)` 和第一轮 system prompt。现有 hook 分批迁移，迁移前后的第一轮讲解保持一致。

## 7. 成本与门槛

- Pro 专属，与现有 AI 讲解一致。每一轮走 `/api/ai`，计入每日用量与限流，不另开通道。
- **缓存**：第一轮和预设问题按 `qid + 题干签名 + 作答 + 问题模板` 缓存在本地，沿用现有讲解的缓存键做法。自由追问不缓存。
- 封顶：每题 6 轮；单轮 maxTokens 沿用 `AI_HELPER_MAX_TOKENS = 2000`；输入约等于证据包（AP 最长也就几千 token）。每轮费用量级与现有一次「AI 讲解」相同，可在 `.ops/deepseek-usage.jsonl` 台账里对账。

## 8. 评估（上线前，离线）

- 抽一组真题当测试集：各题型若干道，覆盖做错、做对、未作答三种情况，每题配 3-4 个典型问题，其中至少 1 个是故意问超出材料的。
- 判定指标（尽量用脚本判）：
  - 引用有效率：`Sx` 存在且引文能在该句里找到
  - 不翻案率：回答从不否定标准答案
  - 超纲拒答率：超出材料的问题给出「材料里没有」
  - 人工抽查讲解是否正确
- 跑评估要调模型。按 DeepSeek 成本护栏，先 `--dry-run` 看调用次数和预估费用，再决定是否跑。

## 9. 风险与未决

- **真题无解析** → 讲解质量全靠模型读原文。缓解手段是 §4 的引用校验和不翻案规则。以后可以离线给真题补「答案依据句」（只标句号，不写讲解），让证据更硬。这一步要单独立项。
- **生成库解析是 AI 写的**，可能和原文冲突 → 标注「仅供参考」，原文与答案优先。
- **听力原文是转写稿**（真题有 `asr_similarity`），个别词可能转错 → 回答涉及具体词时提示「以音频为准」，并给出可点播的那一句。
- 自由追问无缓存，是成本的主要变量 → 每题 6 轮上限 + 每日用量兜底；上线后看台账再调。

## 10. 第二期：错题本复盘（备忘，本期不做）

- **趋势和规律由代码算，不交给模型**：各题型错误率随时间的变化、反复错的题、「和上次错得一样／换了个错法」（`classifyDrill` 已有）。模型只负责把这些数字讲成话，不得自己估数。现有「AI 问题分析」只覆盖拼句（`components/MistakeNotebook.js`），从这里扩到全科。
- **「修正备考思路」必须有可引用的方法库**：先写一份按题型的定位方法 + 陷阱类型说明（口径对齐 `docs/eval-spec/`），建议只能引用它。数据里看不出的习惯不下判断（现有记录只有作答和对错，没有阅读顺序、停留时间这类行为数据）。
- 遵守 2026-10-06 的拍板：错题本不做掌握判定、今日队列和间隔重复。复盘只给总结、建议和「按薄弱题型去练错题」的入口。
