## 1. 桥接：为什么要新写一条，闸在哪

第二来源（商家重排版）的听力分组能靠**逐题音频的文件名**（`listening_m1_q13_q14_conversation_x.mp3`）当 ground truth，
`scripts/realbank/merge_vendor_asr.py` 就是照着文件名重建分组的。第一来源没有这个东西——音频只有整块的
`ListeningModule1/2.mp3`——但每套自带一份排得很整齐的逐字稿 PDF（`Module / Choose the best response /
Conversation1 / Announcement2 / Lecture1`）。所以新写了 `scripts/realbank/merge_first_source_asr.py`，
**把逐字稿 PDF 的分段当分组 ground truth**，产物形状与 `merge_vendor_asr.py` 完全一致
（`merged_asr` 标记 + `transcript_final` / `turns` / `speakers` / `asr_similarity`），
后续 `audit_answers` / `build_bank` / `render_real_audio` 零改动。

### 1.1 与 spec 的一处偏离：音频不切片

spec 要求「ffmpeg 按对齐出来的区间切出逐题音频」。**没有做，也不该做**：真题上线的音频一律由
`render_real_audio.mjs` 用自家 TTS 按 `transcript_final` 重配（那个脚本的头注写着原因：考场原音内嵌作答静音、
且不是我们能分发的素材），原始 mp3 从来不进产物。切片会白白产出一批永远不会被用到的文件，还多一个出错面。
对齐算出来的时间区间保留在 `audio_span_sec` 字段里，用途只有两个：核对与判性别。

### 1.2 四道 fail-closed 闸

| 闸 | 判据 | 拦住了什么（实测） |
|---|---|---|
| **分组校验和** | 「LCR 句数 + Σ 各段固定题量（对话/通知 2 题、讲座 4 题） == 该 module 的总题数」。28 个 module 逐个验过全对；对不上就退回「屏幕材料屏」那条路，还对不上整组扣下 | 屏幕侧的「Listen to a conversation」材料屏在 1.21A 这种合集卷里被 OCR 与题目屏糊成一块（甚至劈成 `Listen to an al` + `nnouncement…`），认不全；校验和这条路不依赖它 |
| **稿子 ↔ 音频序列对齐** | 逐字稿各段按顺序拼成词序列，与 Whisper 整块转写做一次 difflib 最长公共子序列；逐段命中率 < 0.60 / 区间缺失 / 塌陷 / 倒序 → 该段扣下 | **1.28A 整卷 0/27**：该卷文件夹里的听力 mp3 是**别套的**（内容与 1.21A 的逐字稿逐句吻合），27 组全扣 |
| **对话角色** | 逐字稿只有少数组带 Man/Woman；A/B 组用音频基频二分（复用 `merge_vendor_asr.diarize`）判「先开口的是男是女」，判不出（两簇中位基频差 < 50Hz、聚类退化、不像轮替）就扣下；完全无标签的直接扣下 | 34 组 LC 因判不出性别被扣（占 LC 总组数约一半）。角色标反 = 题干问 the man 却问空气 |
| **材料截断** | 结尾没有句末标点 = 被 PDF 换行/分页砍掉了。**这条查不出来的部分靠不了对齐**：截断是前缀，与音频的命中率照样 1.0 | 复述句 7 条、听力材料 1 条 |

口语侧：复述句以文档为准（答案 PDF），Whisper 只用来核对；**面试题第一来源没有任何文档 ground truth**
（答案 PDF 只抄了复述句、逐字稿 PDF 只有听力两个 module），按第二来源口径整组扣下，15 组一条没收。

### 1.3 中途按实测补的三处

1. **复述句被答案 PDF 换行截半**（3.14 第 7 句只剩「…call us on the helpline and we will」）。真因是上游 ingest 按**行**取答案。
   在桥接里重解析答案 PDF 的 `Listen and repeat` 编号列表、把续行拼回去——仍是文档来源，没拿 ASR 顶。14 套里救回 7 句。
2. **LCR 题号错配**：2.1C 的 OCR 只在 12 屏里认出 2 屏带「Choose the best response」，原先按「屏幕认出来的第 i 个 LCR」
   去配「稿子里的第 i 句」，结果 Q12 配了第 2 句。改成：校验和过了 LCR 题号就是确定的 1..n。该卷盲审一致率从 72.7% 回到 …（见 §3）。
3. **题面脏东西**（Opus 复核发现后治的根，见 §5）：逐字稿里残留的播放器时间戳 `{ 1:52 }`、
   材料结尾串进来的下一题题干、`B;` 这种分号说话人标签。

覆盖：对齐正确、顺序颠倒扣下、区间倒序/塌陷/缺失各自扣下、屏幕分组、题号区间推导 + 校验和、

## 3. 源料缺陷（本次新发现，都是闸拦下来的）

1. **1.28A 的听力 mp3 不是本卷的**。文件夹里 `2026新托福真题05-听力音频-Module1/2.mp3` 的内容与 **1.21A** 的逐字稿逐句吻合
   （"Where can I find the class notes" / 退毛衣 / 去邮局…），与本卷自己的逐字稿 0 命中。整卷听力扣下。
   注意两卷时长不同（576.5s vs 549.3s），不是同一个文件的副本，是同一批内容的另一次投放。
   **可恢复性**：本卷的逐字稿 PDF 与试卷 PDF 是自洽的，缺的只是能交叉核对的音频；若别处能找到正确 mp3，重跑 `asr_cache` + 合流即可。
2. **2.1C 的口语 mp3 不是本卷的**。音频讲「大学体育赛事引导」，答案 PDF 与试卷讲「图书馆自助借还」。7 句复述全扣。
3. **1.21A / 2.1C 的截图 OCR 题号本身错位**。1.21A 的材料屏与题目屏被糊成一块、Q19 的题干挂在 Q20 上；
   2.1C 的材料结尾串着下一题题干、题干与材料完全不搭。两卷盲审一致率 63.9% / 63.2%，
   按「不一致必须人看」的口径**整卷听力下架**（连"一致"的题也不可信）。
4. **同一份料换日期反复投放**。第一来源 14 套之间、以及与第二来源之间都有重复：材料 Jaccard ≥ 0.8 成簇后
   听力 19 条、复述 4 整套。每簇留一条。

1. **另 39 套无逐字稿的卷怎么办**。本波能做，靠的是「逐字稿 PDF 提供了权威分组 + 权威文本」。没有逐字稿的卷，
   材料文本只能来自 Whisper，分组只能靠屏幕 OCR——而本波实测屏幕 OCR 的材料屏识别在合集卷版式下认不全、
   题号还会错位（1.21A/2.1C 就栽在这上面）。建议：**不要直接铺**。可行的替代是先只做 LCR
   （刺激句是单句、Whisper 转写可靠、每题独立不吃分组），LC/LA/LAT 等有逐字稿再说。
2. **面试题（15 组）没有文档来源**。音频里有，Whisper 也转得出来，但按第二来源口径「文档没有就 hold」全扣了。
   若要放行需要拍板：面试题是开放式口语题、没有唯一答案，错一个词的代价远小于选择题，
   可以考虑允许「ASR 转写 + 人工过一遍」这条路。放行方式是改 `build_speaking` 里那段注释标明的口径。
3. **34 组 LC 因判不出说话人性别被扣**。基频二分对同性别对话、或录音条件差的对话分不开。
   可选的加强：改用 Azure/pyannote 的说话人分离（2026-07-16 的 Azure spike 已证可用），或人工听一遍标性别。
4. **1.28A 的正确听力 mp3**。逐字稿与试卷自洽，只差能核对的音频；找到就能补回 27 组。
5. **`build_bank` 与 `render_real_audio` 并发跑会互相覆盖题库文件**（本次踩到：配音在后台写 `audio_url` 的同时
   重建把文件整个重写，下架过的条目被写回来了）。两个脚本都不加锁，实操上必须串行；值得在脚本头注里写一句。
6. **1.21A / 2.1C 若要救**，路子是回去修上游 `ingest_set` 的题号对齐（材料屏与题目屏糊成一块时的切块），
