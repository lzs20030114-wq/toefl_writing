# 真题录入链路 + Prompt 审查（2026-09-14）

用户要求：在动手补题之前，先审清楚「现在线上这些真题是怎么被录入的」，再审现在的 prompt。

审查范围：`data/realBank/` 全部 12 个题型（**3675 道在线真题**，`sets.json` 的 inventory 口径）的录入链路，以及链路里所有花钱的
prompt。只读，未改任何数据与代码。生成库（`data/reading/bank/` 等，走 routine 出题）不在本次范围
——那是**生成**不是**录入**，两条链路的判据完全不同。

---

## 0. 一句话结论

**Prompt 写得是对的，问题在于没有机械校验去兑现它的禁令。**

`NO_SOLVE` 明令「绝对禁止解题」、`OCR_NOTE` 明令「不要补写、不要润色」——但整条链路里
**没有任何一道校验把模型输出与 OCR 输入对账**。模型是否忠实转写，全靠它自觉。
唯一例外是听力（有 ASR 词级对齐）与造句（有拼装机械校验），而这两科恰好是我之前建议跳过的。

## 2. 防线地图：每个题型被几道闸把着

| 题型 | 结构校验 | 忠实度对账（输出 vs 输入） | 第二票（盲审） | 落库闸 |
|---|---|---|---|---|
| ctw | `verifyCtw`：答案词在段内 / ≥30 词 / 无中文 | **无** | **无**（无选项，进不了盲审） | 源料体检 |
| rdl / ap | `verifyMcq`：3~5 选项 / 不重复 / 非空 / 无中文水印 | **无** | **有** | 盲审闸 + 复核清单 |
| lcr/lc/la/lat | `verifyMcq` + 合流三层交叉核对（屏幕↔逐字稿↔音频） | **有**（`asr_similarity` 词级命中率） | **有** | 盲审闸 + `merged_asr` 必需 |
| repeat | 句子形态（词数/无中文） | —（零 token，无模型介入） | 无 | 源料体检 |
| interview | — | — | 无 | 人工切分表 |
| bs | **有**：答案句必须能被「模板固定词 + 词块」按序恰好拼出（零 token） | **有**（同左，拼不出即废） | 无 | 跨卷答案句去重 |
| email / disc | 字段完整性（`scenario` 非空 / `goals`≥3 / `students`≥2） | **无** | **无** | 源料体检 |

### 2.1 盲审覆盖面（`audit_answers.mjs:204`）

```js
if (!Array.isArray(it.options) || typeof it.answer_index !== "number") continue;
```

**只有「有选项 + 有答案下标」的题进盲审。** 所以填词、复述、面试、造句、邮件、学术讨论
——**六个题型、2212 道题（占在线真题 60.2%）——从来没有过第二票。**

盲审脚本自己的头注对这件事是诚实的：

> 结构化阶段的校验器只查得了「结构对不对」…查不了「答案有没有错位」
> 一致 ≠ 正确（模型也会做错题），但**不一致必须人看**

它的定位（复核清单而非通过/不通过判决）是对的，问题只在覆盖面。

## 3. Prompt 审查

链路里花钱的 prompt 共 4 处（`structure_set.mjs` 3 处 + `audit_answers.mjs` 1 处），
另有看图类 prompt（`ctw_vision_transcribe.py` / `vision_mcq.js` / `extract_bs_pages.py`）。

### 3.1 共用护栏：写得好

```
NO_SOLVE:  绝对禁止：不要解题、不要判断哪个选项正确、不要输出 answer 字段。
           正确答案由调用方从官方答案页注入。
OCR_NOTE:  只转写你在文本里真实看到的内容，看不到就留空，
           **不要补写、不要润色、不要翻译**。
```

与 CLAUDE.md「出题不许自由发挥」「LLM 只转写不解题」的原则完全一致。**措辞层面挑不出问题。**

### 3.2 `PROMPTS.mcq` — 好，且有一条很关键的设计

> "options" 必须是**数组**，且**严格按屏幕上从上到下的原始顺序**排列。顺序即答案编号，**错一位整题作废**。

把「顺序即答案」这件事说破，是对的——因为答案是按下标盖上去的。
而且它专门写了一段对抗真实失败模式的说明（选项长得像材料片段时怎么分辨），
说明这条 prompt 是被实际事故迭代过的，不是拍脑袋写的。

**但**：这条约束**没有任何机械校验**。模型把选项重排了，`verifyMcq` 全绿。
唯一能抓到的是盲审（重排后模型会选到别处去）——所以阅读选择题实际是靠第二票兜底的，
不是靠这条 prompt。

### 3.3 `PROMPTS.ctw` — 这是全库最薄的一环

填词 prompt 要求模型「还原原文并标出空位」，输出 `passage`（补全后的完整段落）。
校验 `verifyCtw` 查的是：

- `blanks` 个数/顺序与答案词列表一致 ✓
- `given` 是 `word` 的真前缀 ✓
- 每个答案词都能在 `passage` 里找到（`\bword\b`）✓
- `passage` ≥30 词、无中文 ✓

**没有一条检查 `passage` 与 OCR 输入是否对得上。**
模型完全可以写出一段包含全部答案词、通顺、≥30 词的**自己编的**英文，四条校验全过。

这不是假设，是已发生的事实：09-13 用 Qwen 看源截图核对救回的块，
**40 块丢句、8 块是模型编造**（3.15 那块编出了 "they were also interested in…"）。

而且：

- 那次看图核对**只覆盖当轮救回的 30 段**，**基线 116 段从未做过**；
- 标记看图来源的 `body_source` 字段写在中间产物里，**`build_bank` 没有把它带进 live 库**
  —— 所以现在从 `data/realBank/reading/ctw.json` 里**根本分不清哪 30 段核过、哪 116 段没核**
  （实查：146 条全部没有 `body_source`）。

填词是全库最大的题型（1459 空 = 在线真题总量的 **39.7%**），却是防线最少的一科。

### 3.4 `PROMPTS.mcq_repair` — 合理，但放大了同一个风险

修复轮把**相邻 3 个块**拼起来重问、指名要第几题。这个设计对（用失败信号当触发器，
而不是拍脑袋阈值），且要求模型必须给出 `q_number`、认不出就扣下。
风险在于：输入里混着邻题的文本，模型更容易把**别题的选项**装到这题上。
09-13 实测确认过这种事——「15 道原『两票不一致』是结构化把别屏的题挂错了题号，看图后翻案」。
依然是靠盲审+看图抓出来的，不是靠校验。

### 3.5 `SOLVE_PROMPT`（盲审）— 有一处值得注意

```
材料里没有依据就选你认为最可能的那个，不要拒答。
```

强制不拒答是对的（拒答会让一致率失真），但这意味着**材料被模型编坏的题，盲审也会硬选一个**
——四选一，约 1/4 概率蒙对、从而放行。

而放行口径是**任一票一致即过**（`hold_policy.auditPassed`：第一票一致，或跑过第二票且第二票一致），
所以对一道材料已坏的题，跑了第二票反而**提高**它蒙混过关的概率。
第二票的设计初衷是救插入句题（四个插入位几乎等价，flash 误判率高），对「答案错位」是对的；
但它默认了「材料是可信的、只是答案可能挂错」——而这正是本次审查发现不成立的前提。

结论：盲审能抓「答案错位」，**抓不了「材料被改写但自洽」**。忠实度这件事，全链路没人管。

### 3.6 看图类 prompt

`ctw_vision_transcribe.py` / `vision_mcq.js` / `extract_bs_pages.py` 是 09-13 之后加的
**事后核对**工具，不是常规链路的一环。其中 `extract_bs_pages.py` 是唯一自带机械校验的：
「答案句必须能被模板固定词 + 若干词块按序恰好拼出」，拼不出即废——
**这是全库最强的一道闸**，造句因此是模型介入最深、却最可信的题型。

## 4. 风险排序

| # | 风险 | 规模 | 现状 |
|---|---|---|---|
| 1 | **填词正文可能是模型编的，且无法分辨哪些核过** | 146 段 / 1459 空（39.7%） | 已有实锤（8 块编造 / 40 块丢句）；基线 116 段未核；`body_source` 未进库 |
| 2 | **全链路没有「输出 vs OCR 输入」的忠实度对账** | 阅读三科 + email/disc | 仅靠 prompt 自觉；听力有 `asr_similarity`，阅读/写作什么都没有 |

**用户的直觉是对的：现在直接花钱补题，是在一条「忠实度无人把关」的链路上加量。**
补进来的题和已有的题一样，没人能回答「这段正文是真题原文吗」。

## 5. 建议：花钱补题之前，先把「可验证」补上

按性价比排，**前两项都是零 token 的**：

### 5.1 给填词补一道忠实度闸（零 token，本机可跑）

听力的做法可以直接搬：把模型输出的 `passage` 与 OCR 原始 `body` 做词级对齐，
算覆盖率，就是阅读版的 `asr_similarity`。
- 覆盖率低 = 模型编了/丢了句 → 扣下或标记；
- 这道闸零成本、可对全部 146 段**回溯**跑一遍，直接回答「基线 116 段干不干净」。

### 5.2 把忠实度证据带进 live 库

`body_source` + 上面的覆盖率分数写进 `data/realBank/reading/ctw.json` 的每一条，
让「这段核过没有」在库里可查。听力已经这么做了（`asr_similarity` / `source_notes` /
`audio_source` 都在库里），阅读/写作照抄即可。

### 5.3 email/disc 补题前，先给它加校验

至少加一条「`scenario`/`professor.text` 与 OCR 输入的覆盖率」，
否则补进来的 108 题与现有 21 条一样无从验证。

### 5.4 然后再谈补题

做完 5.1~5.3，补题才是「可验证地补」。届时 `--dry` 摸底 → 小批真跑 → 用新闸看回收质量，
而不是看回收数量。

## 7. 追查：阅读题「丢选项」（用户 2026-09-14 提出）

### 7.1 先复现：成品库里**找不到**丢选项

| 检查 | 真题 AP/RDL | 生成库 reading |
|---|---|---|
| 选项数 | 690 题**全部恰好 4 个**（另 3 道选句题走 S 键） | 1318 题，除 1 道 5 项外全是 4 个 |
| 同篇内两题选项集雷同（串栏典型症状） | 0 | — |
| 乱码 / U+FFFD / 中文混入 | 0 | — |
| 插入句题正文标记 `[A][B][C][D]` 齐全 | 26/26 齐全 | — |
| 选项开头被砍 | 0（首轮"发现"的 8 条是本次排查自己 `slice(-30)` 截出来的假象，数据无损） | — |

唯一实锤缺陷：`real_ap_21b_2_12` 的插入句题，选项不是 `[A]`~`[D]` 四个位置标签，
而是带残括号的正文碎片（`"[] AI predicts…"` / `"records. [ AI systems…"`）。26 道里 1 道。

### 7.2 真实机制：丢选项 = **整题作废**，而且成品库里看不出来

`build_bank.optionsMap` 的注释写得明明白白：

```js
/** 选项数组 → {A,B,C,D}；不是 4 个就返回 null（整题作废）。 */
```

所以成品库里 100% 是 4 选项，不是因为没丢过，而是**丢了的那些根本没进来**。
落库日志里有一行专门数它：

```
选项残缺丢弃 N 题（OCR 串栏，非 A-D 四选项 / answer_index 越界）
```

### 7.3 三层口径不一致，钱花了两遍才扔

| 层 | 对「3 个选项」的态度 |
|---|---|
| `PROMPTS.mcq` | 「选项通常 4 个，**也可能是 3 个**；有几个写几个，不要凑数」→ **明确邀请** |
| `verifyMcq` | `<3 或 >5` 才报问题 → **3 个照样 `status: "ok"`** |
| 盲审 `audit_answers` | 照常审它 → **花第二笔钱** |
| `build_bank.optionsMap` | 不是恰好 4 个 → **整题作废** |

一道被 OCR 吃掉一个选项的题：先花结构化的钱转写，再花盲审的钱审，最后在落库那一步被静默丢弃。

### 7.4 最要命的一点：它被永久困死，重扫也救不回

`--only-failed` 的重扫判据是「状态不是 ok 就重扫」。而 3 选项的题在 `verifyMcq` 眼里是 **ok**，
于是：

- `--only-failed` **永远不会重扫它**（`shouldResweep` 判 `already_done`）；
- `build_bank` **每次重建都照样扔掉它**。

**这批题处在一个死循环里：不会被重试，也永远进不了库。** 这解释了为什么前几轮反复重扫，
某些篇子的题数始终补不满 —— 缺的那几道压根不在重扫的名单上。

### 7.5 这个损失没有任何留存

- `data/realBank/reading/counts.json` 只记最终条数（`{ctw:146, rdl:125, ap:86}`）；
- `droppedBadOptions` / `droppedInsert` / `droppedDupStem` / `droppedNoAudit` 这些丢弃计数
  **只 `console.log` 到终端**，跑完即散；
- `--report` 是可选参数，且只写 `counts_after` 与扣留台账，不进 git。

所以「这一轮丢了多少题、丢在哪、为什么」事后无从查证——这正是为什么只能等用户撞见
「这篇怎么只有 1 道题」。

### 7.6 建议

1. **统一口径，且要早拒而不是晚扔**。真题阅读就是四选一，3 个选项必然是 OCR 吃了一个。
   把 `verifyMcq` 改成「阅读选择题必须恰好 4 个选项，否则 flagged」：
   - 这道题立刻变成可重扫的（`--only-failed` 会捡它），**从死循环里放出来**；
   - 省掉它在盲审上白花的那笔钱；
   - `PROMPTS.mcq` 里「也可能是 3 个」这句要同步删掉——它在邀请模型少给选项。
   （听力的短应答等题型若确有 3 选项形态，按题型分别设阈值，别一刀切。）
2. **把落库丢弃计数落成账本**，按 (卷, 科, 题号, 原因) 写进文件并纳入 `loss-ledger`。
   丢题账本现在只能算出「缺口」，算不出「丢在落库这一步」——补上这一层，
   §4 风险表里的「未知」才能变成数字。
3. 修 `real_ap_21b_2_12` 那道插入题（1 道，走复核清单）。

**注意：本节没有改任何代码。**「3 选项的题实际有多少道」要在本机跑才知道
（要读 `.codex-tmp` 的结构化产物），跑一次 `build_bank --dry` 看那行日志即可。
