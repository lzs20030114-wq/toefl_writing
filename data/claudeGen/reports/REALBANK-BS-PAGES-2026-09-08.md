# 第一来源截图卷「造句题」入库报告（2026-09-08）

## 一句话

第一来源（2026 年 1–5 月机经卷）的写作 PDF 是**考试界面截图**，没有文字层：
`structured.json` 只有答案页给的 `{n, sentence}`，题面（模板 + 词块）一直缺，
所以 build_bank 把 436 条 build 判为 thin 丢掉。这次补上缺的那一半 ——
识图拿题面、答案句仍来自答案页，两边用**零 token 的机械校验**对上，
造句真题从 **106 题 / 12 套** 长到 **292 题 / 41 套**。

## 做法

1. `scripts/realbank/extract_bs_pages.py`（新增）：pymupdf 按页渲染（dpi 120）→ Qwen3-VL 识图
   （复用 `ocr_images.py` 的客户端 / 估价 / 缩图；`call_qwen` 加了可选 `prompt` 参数）。
   页图缓存 `.codex-tmp/realbank/bs-pages/<卷>/p<N>.png`，识图缓存
   `.codex-tmp/realbank/bs-ocr/<卷>/p<N>.<图hash8>.json`（键含图 hash，重跑零调用）。
2. **关键设计：不信 OCR 数下划线。** 首轮 3.16 只过 4/10，全栽在「模板里 4 个空被看成 3 个」。
   改成只把模板里的**给定词**当锚点、空位个数由「答案句 + 词块」自己解出来后，3.16 变 10/10。
   识图只负责认字，不负责数下划线。
3. **机械闸（拒收即丢，绝不让模型猜答案）**：答案句去掉给定词后，剩余词序列必须能被词块
   **按顺序、不重叠、恰好**拼出（词口径 = `lib/realBank.js` 的 `bsNormWord`）；
   未用到的块 ≤ 1（即 distractor）；解必须唯一（多解且用块集合不同 → `ambiguous_solution` 拒收）；
   最后再跑一遍 `deriveBsPrefilled` 的对齐。
   `answer` / `blanks` 用**截图侧**的原始大小写与标点回填（答案页是全小写无标点的二手转写）。
4. **落库**：产物 `.codex-tmp/realbank/<卷>.bs.json` → `build_bank.mjs` 的 `buildWriting()` 读入，
   与 rf 卷走同一套 meta / 同一套闸（source-flags blocking、卷级 hash 去重）。
   新增两道闸：**答案句归一化跨卷去重**（先入库者留，卷名排序 = 数字卷在 rf 前 = 日期早的留）
   和 **runtime 渲染闸**（`scripts/realbank/bs_runtime_gate.mjs`，真的 `runtimeModel` 跑一遍，
   过不了的不收 —— 以前这种题会躺在库里由前端静默丢，导致批次卡题数虚高）。

## 抽检（15 题，逐张比对页图）

随机 15 题全部打开对应页图逐字核对 **prompt / 给定词 / 词块 / 答案 / 干扰块**：

- **15/15 答案句、题干句、给定词与截图完全一致**；`bs_225_06` 的干扰块 `stopped` 也对。
- 抽检过程中发现并修掉一个保真问题：给定词里的内部标点被剥掉，
  `No, but ___` 变成 `No but ___`、`Yes. Do ___` 变成 `Yes Do ___`。已改成
  「剥标点只用于对齐，回填句子用屏幕原样」，重跑后 `No, I have other plans.` / `Yes. Do you know…` 正确。
- **1/15 有粒度偏差**：`bs_32a_01` 屏幕上是 5 个词块（`that recently` / `to` / `opened downtown` / `the` / `restaurant`），
  识图把两个多词块拆成了单词，落库成 7 块。答案、题干、给定词都对，题**可做且判分正确**，
  只是拼块粒度比原卷细一档。这是「词块靠视觉间距切分」的固有噪声，机械闸拦不住（拆细了照样能拼回答案）。

## 拒收原因分布（共 39 条，按量）

{
 "no_solution": 19,
 "_fuzzy_word_ok": 12,
 "too_many_spare_chunks(2)": 2,
 "missing_template": 1,
 "no_answer_sentence": 6,
 "duplicate_chunks": 9,
 "duplicate_q": 2
}

- `no_solution` 19（最多）：词块拼不回答案句。多为识图漏块/多块，也有答案页与题面本就对不上的。
- `duplicate_chunks` 9：屏幕上出现两个完全相同的词块（如两个 `the`）。runtime 要求 bank 内词块互不相同，一律拒收。
- `no_answer_sentence` 6：答案页缺该题（3.6 的答案页只覆盖 6 题）。
- `too_many_spare_chunks(2)` 2：多出 2 个用不上的块（runtime 只支持 1 个 distractor）。
- `duplicate_q` 2 / `missing_template` 1：3.6 有 A/B 两份写作 PDF，B 卷题号与 A 卷撞，取先出现的。
- 另有 12 题靠**单字符编辑距离**容错通过（答案页 OCR 错字，如 `broshure`→`brochure`），
  拼写取截图侧；每题最多容一个词，且整句其余部分逐词精确对齐。

## 遗留

1. **3.10 的「写作.pdf」其实是听力 LCR 页**（22 页全是 Choose the best response），识图正确返回 0 题，
   该卷写作本来也被 source-flags 标了 blocking。源料标签错，不是管线问题。
2. **词块粒度噪声**（见抽检）：估计个位数百分比的题拼块比原卷细。要治只能改识图 prompt 重跑（再 ¥2.5 左右）。
3. **小批次**：按 source 分批后有 3 套只剩 1~3 题（`4.5`=1、`rf0615`=1、`3.6`=3、`3.23`=3、`4.28`=3），
   前端会渲染成「第 N 套 · 1 题」的批次卡，观感偏碎。是否合并/隐藏小批次要产品拍板。
4. **`build_bank.mjs` 全量重建不可用**：`.codex-tmp` 里的结构化产物远多于已入库的量
   （全量跑会把阅读 AP 99→210、听力 LCR 118→124 一次改掉四科，那是「铺量拍板」那件事）。
   本次落库走新增的 `--only-bs`：只写 `writing/bs.json`，applyReview 顺手重写的 10 个非 bs 文件
   按字节还原，已验证四科文件逐字节未变。
5. 1~2 月共 11 套卷（1.21 A/B/C、1.27 A/B、1.28 A/B、2.1 A/B/C、2.10 等）**根本没有写作 PDF**，造句无从抽取。
