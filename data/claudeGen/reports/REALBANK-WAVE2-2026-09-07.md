## 6. 口语题池回收（2026-09-07 补跑）

§5 里挂着的两处题池口语缺陷已修并回收落库。

### 6.1 根因（比 §5 的描述更细）

两条其实是**同一个根**：题池的一块 `Listen and Repeat` / `Take an Interview` 底下并排放 3~6 组，
每组题号都从 Q1 重数，而解析器把整块拍平成一个 `{题号: 内容}` 字典 —— 5 组的 Q1 互相覆盖，
`" ".join` 之后就成了「Enter your name and student ID number. Measure carefully to avoid mistakes. Stor…」
这种整段（与该题 ASR 相似度 0.31）。组号能对上的那几套（`_s01_q03` / `S-R01_q1`）则因为
音频那边算的是 `set*100+q`、文档那边算的是裸 q，一条也查不到，全报 `no_sentence_in_doc`。

源料里的分组写法一共 6 种，全部覆盖：
`Task 1.2: 标题`（7.04）、`Listen and Repeat Set 2: 标题`（7.05 / 7.11）、`Listen and Repeat - Set 2`（7.18 / 7.19）、
标题行 + `TOEFL Real Practice Set 28 · Module 1 · Questions 1-7`（7.25 / 7.29）、
`Form B | 标题` + 裸 `1.` 或 `B1.` 两种题号（8.12 / 8.19 / 8.22 / 8.30）。

### 6.2 修法

- **`parse_reformatted.py`**：口语两块改成按组解析（`ak.repeat_groups` / `ak.interview_groups`）。
  分组边界**不按标题行切**（题池答案页里混着 `July 29 Recall · 14` 这类页眉噪声，按标题切会把一组劈碎），
  而是按「题号回到 Q1」判；组号取上一条组标记（Set / Form 字母 / Task n.m），认不出就用出现顺序。
  `A1.` / `B7.` 这种「组字母 + 题号」只在本组字母对得上时才认。
  复述块的续行加了防串组：复述句就是一句，上一句已经以句末标点收尾就不再往上接。
- **`audio_names.py`**：`speak_unit` 多返回一个 `q`（组内序号）；新增 `align_speaking_groups()` —— 三级对位：
  ① 文件名带组号就按 `(组号, 组内序号)` 直取；② 只有一组（第一波）按题号直取；
  ③ 都不成但「文档条数 == 音频条数」按顺序对位（7.04 / 7.18 这类「文档分组、音频拉通编号」）。
  仍对不上的给出「同组内序号相同」的候选列表。
- **`merge_vendor_asr.py`**：`build_speaking` 是照音频目录重建口语组的，拿不到解析器内部的 AnswerKey，
  所以解析器把答案页分组写进 `structured.speaking_key`，合流阶段直接吃。候选句逐条与 Whisper 逐字稿比
  相似度，**≥0.6 才认**（8.12 就是这么定的：答案页 3 组、Speaking.docx 只写了 1 组的 `Audio:` 行）。
  对不上的是**单句** hold，不牵连同组其它句。
- **8.22 / 7.19 的 `no_sentence_in_doc` 另有一半是 OCR 覆盖不全**（答案 PDF 分别只缓存了 8/23、0/14 页），
  补跑 Qwen-VL 29 张后口语块才出现在答案行里。
